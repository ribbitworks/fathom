# Setting Up Fathom

How a Workforce Administrator sets up a new Fathom, from an empty database to an organization others can plan with. Installing Fathom makes its first account, Fathom Administrator. Before starting, an Administrator signs in with it, makes the Workforce Administrator's account, and sets the time zone, as [Working as an Administrator](working-as-an-administrator.md) sets out.

## Fill In the Lists

Columns pick their choices from lists. A new Fathom has only the lists its own columns need, such as **Positions** and **Hiring states**.

1. Select the **Lists** page.
1. Open **Positions** and add the organization's positions, as [Lists](lists.md#add-choices) sets out. Pasting one per line adds many at once.
1. Check **Hiring states**, whose choices start with one for each meaning, and rename or add to them.
1. Make any other lists people are described by, such as sites or levels, as [Lists](lists.md#make-a-list) sets out.

## Add Columns to People

1. Select the **People** page.
1. Add a column for each list made, and any web link, note or number columns, as [People](people.md#add-a-column) sets out.
1. Give a column holding private details the **Personal** or **Confidential** class, as [Data classes](data-classes.md) explains.

## Add the People

1. On **People**, paste the rows from a spreadsheet into the empty row at the end of the table, as [People](people.md#add-a-person-or-a-planned-hire) sets out.
1. Tick **Manager?** for everyone who manages others.
1. Choose each person's **Manager**, as [People](people.md#give-someone-a-new-manager) sets out.
1. Name each manager's team in **Team name**, on the manager's own row.
1. Add the planned hires, choosing a hiring state in **State**.

## Set Up Planning

1. Select the **Releases** page, and add a release stream for each product line, with its cycles, as [Releases](releases.md#add-a-release-stream) sets out.
1. Select the **Capacity** page, and set the hours and working days, as [Capacity](capacity.md#change-a-setting) sets out.
1. Select the **Org chart** page, choose **Feature teams**, and add each feature team with its lead and members, as [Org chart](org-chart.md#change-a-feature-team) sets out.

## Have the Changes Approved

Most of these changes are drafts: nobody else sees them until they're published, and they go live once approved.

1. Select **Publish** in the top bar, which says how many changes are waiting.
1. Ask the Engineering Director to approve them on the **Drafts** page, as [How Work Moves Between Roles](how-work-moves-between-roles.md#approve-the-drafts) sets out.

The planning settings on **Capacity**, and a team's colour, change at once, with no draft. [Drafts](drafts.md) explains the marks drafts show while they wait.
