# Unpublished Drafts

- **ADR:** 0008
- **Status:** Accepted
- **Date:** 2026-11-03
- **Revised:** 2026-11-17, to publish or discard chosen changes, and to mark a change set published once none of its changes is held; 2026-11-20, to publish only the changes the role in use may make; 2026-11-25, to keep them as private changes, by record and user in each user's set, each standing over the published draft with its maker's own fields; 2026-11-26, so changes no longer hold their record, and count in no other user's checks; 2026-11-26, to discard everyone's changes to a record that goes away, shown to their maker alone; 2026-11-27, to count a private change from when it is published; 2026-11-27, to ask which value to keep for a field someone else changed meanwhile, or a record one of them removed, and to give up a field the role no longer sees; 2026-11-27, to catch a removal of a record changed live since it began, and to publish a change to an addition approved meanwhile against the live record; 2026-11-27, to check the plan's records, lists, choices, columns and people again on publishing by their own rules

## Context

A user's changes are seen only by that user until they publish them:

- **Publishing and discarding:** They publish or discard them all at once, or chosen changes with those they must go with.
- **Nothing held:** Others see a record without anyone else's unpublished changes, and may change, approve, reject, discard or resubmit it meanwhile.
- **Published drafts:** Changing a published draft makes the change the editor's alone until they publish it, while others keep seeing the published draft.
- **The change history:** It shows unpublished edits only to their maker until they are published.

[ADR 0007](0007-draft-rows.md) keeps drafts in one table, one per record, shown to everyone. Some records exist only as drafts, such as a person or a list drafted to be added.

## Decision

- **A table of private changes:** A user's unpublished changes are kept in a second table, shaped as the table of drafts, keyed by the record and the user whose changes they are, in that user's set. Several users may each have one for the same record.
  - **Whole drafts:** Each row holds the whole draft the user intends, as a draft row does, not the difference from the published draft.
  - **Own fields:** Each row records, for each field its maker changed, the value it started from. Read and published, it puts those fields over whatever the published draft holds then, so a change made by another meanwhile to other fields stays; a row naming no field of its own, such as a record its maker adds, or changing the action, such as a removal, keeps the whole draft.
  - **A record that goes away:** when an approval removes a record, with a list's choices and order, or publishing a discard or an undo removes the published draft that added it, everyone's rows changing it are discarded. Each is recorded in its maker's history as a withdrawal of the fields they changed, with its access history, which only they see, as a change set of its own kind that is never published and leaves the maker's other private changes as they were. A row whose fields are by then no different from everyone else's, such as an order now the same, is recorded as taking back each of its maker's changes to it, so every record withdrawn is named, with no access history, since no value changes.
- **Nothing held:** An unpublished draft holds nothing. Anyone may change, approve, reject, discard or resubmit the record meanwhile, and the user's own changes update their unpublished draft, starting from the published draft when there is one.
- **Read per user:** Reading a table puts each user's own unpublished drafts over the published drafts, and never reads anyone else's, nor says who has them. A record that exists only as someone else's unpublished draft is not shown at all.
- **Publishing moves the rows:** Publishing writes each of the user's unpublished drafts, its own fields over the published draft for the same record, waiting for approval, and removes them, all in one transaction.
  - **No change left:** An unpublished draft that no longer changes anything removes the published draft.
  - **Discarding:** Discarding removes them.
  - **Chosen rows:** Publishing or discarding chosen rows works the same way on those rows alone, with the rows the server adds to them:
    - **On publishing:** the user's own rows they use, the rows saved in the same change set, and the rest of any fill.
    - **On discarding:** the user's own rows that use them, and the rest of any fill.
  - **The server's answer:** The server answers each of the user's rows with its key and the rows it goes with, so the page ticks them together.
  - **Fields someone else changed:** Publishing checks each row's own fields against the values they started from, comparing only with the published drafts and live records. A field whose value now, in the published draft or live, is another, and not the user's own, refuses the whole publish, saving nothing, with each such field: the record, both values as the change history shows them, by its rules, a column's with its table's records, and who made the other.
    - **Keeping a value:** The user then publishes again saying, field by field, to keep theirs or the other, for the other side as they were shown it. Keeping the other drops the field from their row, so the published draft's value, or the live one, stands; a row left with no field of its own changes nothing. Fields nobody else changed go through without asking.
    - **Shown again:** A side kept for another side than the one there now, since someone else changed it again after the user was asked, is asked about again.
    - **Recorded as given up:** What is given up is recorded as a change set of its own kind, given up, never published and never undone, with one change for each of the user's changes still private that it takes back, by the action that undoes it, a private discard of a draft included. A change set still private holds nothing published, since changes saved together are published together and withdrawing changes to records gone closes no other set, so each takes back exactly a change not yet published. Each change given up names the change it takes back, and a change is taken back at most once, which the database holds to, so a change given up once, or a discard already taken back, is never given up again. A give-up takes back only the user's changes since they last took the record back by hand, by discarding their changes to it by choice, or by reverting every field, which leaves no private change: those before, and their taking back, count as they would with no clash, as reverted edits do. Undoing a private change set leaves it and its undo out of what a give-up takes back, since they cancel each other, while an earlier change still standing is taken back; undoing a change set already published starts nothing again, since what it puts back is the user's standing change. The changes and discards taken back count neither for who last changed the field, nor for whether the user needs another approver, nor as a decision that starts a draft's history again, even once their change sets are published with the user's next changes, while a change the user published before still counts.
    - **Discarding by choice:** Discarding a private removal of a record only drafted to be added, by choosing it, gives up that removal the same way, so it never starts the draft's history again. So does undoing the change set that removed it, by the same step.
    - **Shown to the user alone:** A field given up shows in the user's history as their change to the draft, from their value to the other. A whole record given up shows its field changes taken back, and nothing for a record's addition or removal taken back, which neither added nor removed it. Everyone else's history still shows the user's original change, as with edits taken back by hand, and not its giving up.
    - **A field the role no longer sees:** A field the role in use no longer sees, by the record's kind or the field's class, that someone else changed since, is given up without asking, keeping the other value, and the answer names it alone, without values. So is a whole record, below, of a kind the role no longer sees, and the user's own removal of a record when any field changed since it began is one the role doesn't see. A side sent for any of them is ignored. Nobody overwrites what they can't see.
    - **A record removed meanwhile:** A row changing a record a published change has removed since, or a row removing a record whose values are no longer those it started from, clashes on the whole record. Taking back a published draft counts as both: over a removal published since it is a change, and taking back a record's addition is a removal. The user keeps their change or the other, for the record rather than a field; keeping the other gives up the whole row, and keeping their change over a removal still gives up the fields their role no longer sees.
    - **Changed live since a removal began:** A row removing a record, or taking back its addition, also clashes on the whole record when a field it never started from was changed live since it began, as the change history records it: when the latest of the user's private changes that removed it was made. The user is told who made that change live, where the history shows it to their role.
    - **An addition approved meanwhile:** A row changing a record only drafted to be added, once the addition is approved, publishes its own fields as a change to the live record. A row taking such an addition back publishes as the live record's removal. Each is then checked as any other row.
    - **Whole drafts:** A row naming no field of its own, such as a record its maker adds, or a take-back of a removal, holds the whole draft its maker meant, so it asks nothing about others' fields, though it is still checked again below.
  - **Checked again:** Once each clash has a side kept, each row is checked against the data as it is now, as the user's role sees it, all of them refused if any fails.
    - **The same rules:** The kinds below are checked by the same functions their fresh changes go through, so the two can't drift apart. Only rules about the request's shape, and the role's permission to make a kind, which Publishing as the Role in Use below sets out, are left out.
    - **The plan's records:** The rules across records, and each kind's own, such as a feature's or a proposal's choices still offered, its feature team still there, an owner still among People, and fields the role may still change.
    - **Lists, choices, orders and columns:** Such as a list or column whose details the role still sees, a name no other list or column has, a list a column now draws on not retired or removed, a choice's meaning that fits its list, a built-in list still offering a choice for all it keeps, and drafts' values that fit a column's settings.
    - **People:** Such as a position or column value still offered, a state that fits, an Employee ID or team name no one else has, a reporting line that closes no loop and keeps reports within their manager's dates, and a manager still free to be removed or unmarked. Adding several people at once keeps its own faster check of the same rules.
    - **Other kinds:** Planned hires and feature teams are not yet checked again.
    - **The refusal:** It names the record and gives the reason a fresh change would get, such as "The feature Login: Choose a status that is offered". A role that doesn't read the record's kind is told only that the change no longer fits, since the reason may name records it can't see.
  - **Other users' rows:** A chosen row that isn't the user's is refused as one that doesn't exist.
- **Publishing as the role in use:** A row changed in a change set made as another of the user's roles is published only when the role in use may make its kind of change.
  - **Rows made as the role in use:** A row changed in a change set made as the role in use is published whatever its kind, since a change may move records of other kinds with it, such as the releases a cycle's new length moves.
  - **Rows left:** A row that can't be published stays, with every row that uses it or was saved with it, and publishing answers how many it left.
  - **Discarding:** Discarding takes back any of the user's rows, whichever role made them.
- **Private change sets:** Each change set records whether it was saved as unpublished changes.
  - **In the change history:** The change history shows such change sets only to their maker until publishing marks them published.
  - **Marked published:** A change set is marked published once its maker has no unpublished draft left of any record it changed, so a change set saved with changes to several records is published once all of them are.
  - **From when a change counts:** Each change set records when others could first see it: when saved, or, saved privately, when its maker published it. Who changed a draft counts each change from then, so a change saved before an approval or discard of its record and published after it still counts, and its maker needs another approver. A decision counts from when it was made, so a private discard published later starts again only what was published before it, and its maker's own changes to the record made before it, published with it or still private. A draft's time, and the day the scope history gives a change, are when it was published too. A change another user publishes between a private discard's making and its publishing still counts, even when the discard's publishing takes it out: a known limit, which errs toward another approver.
  - **Changes to a record gone:** A change withdrawn because its record went is never published, so nobody but its maker ever sees it, nor its withdrawal.
    - **Their own change sets:** A change set still private that changed a record gone is never published.
    - **Saved with others:** The history can only be added to, so a change set that also changed records that stay is replaced, at its own time and role, by two copies: one of its changes to the records gone, never published, and one of the rest, published as the change set would have been. The change set itself is then shown to nobody, and its maker's history reads as their change, then its withdrawal. The copies keep its time, and whatever orders changes as made, such as undo's check for changes since and the unpublished list, orders them by their change set's time, then as saved, so the copies stand where it stood. Like any private change set, the copy of the rest is stamped when its maker publishes it, which is when it starts to count for who changed a draft.
  - **Undo:** Undo works on them as on any change set, putting back the unpublished draft. A withdrawal because a record went can't be undone, since there is no record to put the changes back on.
- **Checks see only the user's own:** Another user's unpublished drafts count in no check.
  - **Taken values:** a name, Employee ID or requisition in someone else's unpublished draft isn't taken.
  - **In use:** a choice, column, list, manager, team lead or state used only in someone else's unpublished draft isn't in use.
  - **The user's own:** a user's own unpublished drafts still count for them, and publishing checks again.

## Consequences

- **Every write path changes once:** The functions that write drafts write unpublished drafts instead, and every read goes through the per-user overlay, so pages need no changes.
- **One schema change:** A new table and a new column on change sets, added by a reviewed migration.
- **Nobody waits:** One user's unpublished changes never block another's work; the top bar's count keeps them in view for their maker.
- **Nothing seen by others:** Nobody else is shown that a record has unpublished changes, or whose, and no refusal tells them.
- **Reading others' changes:** A request that removes a record reads the private changes of everyone who has changed it, before and after, inside the drafts lock; one that removes nothing reads none.
  - **Who changed a draft:** The makers a draft shows, and the check that an approver didn't change what they approve, read everyone's private change history for the records they cover, to leave out each change a change given up names. They count each change from when others could first see it, and a decision from when it was made. They reveal nothing: a change given up names only its own maker's private change, another user's private changes count for nobody else, and their private discards start no draft's history again, so what is shown and refused is the same whatever anyone else holds privately.
- **Nobody's value lost unasked:** Two users may change the same field, or one remove a record the other changes; whoever publishes later is shown the other's change and chooses which to keep, so neither replaces the other without knowing. A field or record the later user's role can't see keeps the other's side.
- **Giving up takes back exactly what it gives up:** Each private change given up is taken back one for one, by name, so the user counts as having changed a draft for what they published, and for nothing they gave up.
- **Reverted edits are published later:** Edits a user takes back by hand before publishing leave nothing to publish, so their change sets stay unpublished until the user next publishes, when they appear in the history with the rest.
- **One exception to an append-only history:** Marking change sets published is the only update the change history allows, limited by the database to that mark and when it was made, from unpublished to published, once.
